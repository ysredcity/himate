# ADR 0009：宿主 header 返回驱动产品逐层返回
- 日期：2026-11-07（Asia/Shanghai）
- 状态：已接受并实施
- 替代关系：部分替代 [ADR 0007](0007-mobile-host-preview-container.md) 中「宿主按钮只展示说明、不驱动产品状态、产品对话内部提供返回首页入口」一条；其余不变

## 问题
用户 2026-11-07 要求：移动端新对话页、对话页不再放单独的返回按钮，改由宿主容器 header 的返回按钮回到工作台首页。宿主与产品分别在父页面和同源 iframe 中，状态不共享。

## 选项
1. 同源 `postMessage` 约定两条消息：产品报告是否可返回，宿主点击时通知产品返回。代价：多一份很小的协议文件。
2. 产品用 `history.pushState` 记录层级，宿主调用 iframe 的 `history.back()`。会改动浏览器历史和地址，刷新与纯网页入口行为难以预期。
3. 宿主直接读写 iframe 内 React 状态。耦合过深，违背 0007 的隔离初衷。

## 结论
采用选项 1。协议在 `apps/mobile/src/preview/host-bridge.ts`：
- 产品 → 宿主 `himate:back-state { canGoBack }`；宿主 → 产品 `himate:host-back`。只接受同源消息，宿主另校验来源为自己的 iframe。
- 产品（AgentShell）按「图片查看器 → 产物面板 → 会话抽屉 → Agent 页回首页」逐层返回。
- 产品没有可返回层级（首页）时，宿主保持原行为：显示「返回宿主应用」说明。
- 纯网页入口（无父窗口）不发送消息，也没有返回按钮；真实宿主接入时需按同一语义对接宿主返回能力。

## 补充（2026-11-10）
同一协议新增产品 → 宿主 `himate:tab-bar { visible }`：AgentShell 在首页时为 true，新对话 / 对话页为 false，宿主据此显示或隐藏飞书 Tab 栏。

## 后果
- 删除新对话页、对话页顶栏的「返回工作台」按钮及 `onBack` 传参链路。
- 宿主返回按钮 aria-label：可返回时为「返回」，否则为「返回宿主应用说明」。
- 刷新或 iframe 重载后产品重新报告状态，初始为不可返回。

## 验证
根 `npm run gate` 通过；Chromium 375/402px 在宿主壳中验证：首页返回显示宿主说明；新对话页返回首页；首页抽屉先被关闭；对话页全屏产物先关闭，再返回首页；页面内无产品返回按钮；无页面错误。真机未验证。
