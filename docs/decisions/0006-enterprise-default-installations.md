# ADR 0006：企业默认安装与个人安装额度

- 日期：2026-11-07（Asia/Shanghai）
- 状态：已接受并实施
- 替代关系：[ADR 0005](0005-expert-directory-and-dispatch.md)中的10位总上限及初始安装规则由本决策替代；目录与宿主边界继续有效。

## 问题

用户要求人事专家、差旅专家由企业默认安装，无法删除且不占用20个自行安装名额；仅靠UI禁用不足以保护规则，需要所有增删与匹配入口一致执行。

## 选项与结论

保持同一份内部安装ID列表，但在expert-data.ts增加enterpriseDefault标识。规则层installedExpertIds统一补齐企业默认、过滤未知ID并去重；personalInstallationCount仅计非企业默认。addScheduledExpert对普通20上限进行约束，removeScheduledExpert无法删除企业默认；自动匹配始终包含企业默认。

没有为两类安装复制列表与路由，也不添加后端。默认种子为两位企业默认加财税 / IT服务 / 采购协同三位普通已安装示例，目录共15条。总安装人数可以达到22（2默认+20个人），Header显示总数；列表Alert说明计额与剩余名额。

## 影响与验证

所有Tab中企业默认Check禁用、不提供删除；普通已安装仅在已安装Tab提供删除。恢复shadcn默认disabled:opacity-50，保留外span Tooltip；安装与详情操作共用组件。4项规则测试验证上限不含默认、默认不可删除 / 不需手动安装、去重 / 补位、匹配与资料有效性。前端Mock状态刷新重置，未接企业安装服务或权限平台。

## 可安装能力约束修订（同日）

用户进一步要求只有支持召唤的专家可安装。canSummon同时约束UI入口、安装函数、名单规范化、计额与自动匹配，进入型旧ID会被过滤。目录可召唤扩至10位，初始5位全部可召唤；Composer选项派生同一列表。企业默认2位与20个个人名额规则不变。

## 后续调整（2026-11-12）

用户将自行安装上限由20位调整为10位（`SCHEDULED_EXPERT_LIMIT`）。规则不变：企业默认2位不占名额；总安装人数上限为12。上文中的“20”均为当时的取值。目前可召唤专家共10位、其中2位企业默认，示例数据下自行安装最多8位，演示中无法触达上限，规则由单元测试覆盖。
