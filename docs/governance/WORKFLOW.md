# 协作与变更流程

## 1. 接手

读取 [统一契约](../../AGENTS.md)、[当前状态](../context/current.md)、[最近交接](../context/handoff.md)。根据任务查阅 [架构](../ARCHITECTURE.md)或 [设计契约](../DESIGN.md)，确认实际目录、依赖和正在运行的服务。

不要将其他 Agent 的聊天摘要直接当作已验证事实。系统 / 开发者约束和用户最新授权优先；仓库文档用于承载项目约定。存在冲突时先检查证据，保留无法确认的差异，不能编造“已经确认”。

## 2. 实施

- 开工时说明本轮目标与改动范围；复杂迁移在 `docs/plans/` 记录可执行步骤。
- 桌面应用在 `apps/desktop-web/`、移动应用在 `apps/mobile/` 修改；根目录脚本承担治理和多应用编排。
- 先复用组件和数据入口，不把场景、颜色和静态数据散入页面 JSX。
- 变更架构边界时写 ADR，记录问题、选项、结论、代价和迁移办法。
- 常规修复在已有授权下直接推进；涉及范围扩展或不可逆外部动作时依据实际授权处理，不建立额外的例行审批门。

## 3. 文档更新矩阵

| 变更类型 | 必须更新 |
| --- | --- |
| 任意有意义的交付 | CHANGELOG `[Unreleased]`、current、handoff |
| 视觉、断点、交互、动效 | 设计契约；有帮助时附验证截图 |
| 工程结构、依赖边界、接口职责 | 架构文档、ADR；必要时 README 命令 |
| 运行 / 安装 / 构建流程 | README、架构文档、相关检查脚本 |
| 纯文案修正或小维护 | changelog 可合并为一条；current / handoff 保持简短，不重复整份规则 |
| 失败、中断或部分完成 | current / handoff 写实际状态、剩余项与可继续命令；不标记成功 |

同一数值和规则以设计或架构文档为唯一事实源，current 与 handoff 只摘要并链接。

## 4. 验证

```sh
npm run gate
```

根 gate 检查治理与应用。针对实际 UI 改动再验证受影响交互和宽度；新增测试应验证有价值的行为，不为纯文案编写重复实现的测试。

交付必须说明：修改内容、实际检查、结果、剩余问题。已知的主包体积提示不能说成“无警告”；未运行的安全审计不能延续上次“0 漏洞”的说法。

## 5. 交接

用 [交接模板](../context/handoff-template.md)覆盖 [最近交接](../context/handoff.md)。记录改动入口、检查命令、服务位置、待办与注意事项；详细历史移入 changelog / ADR，current 与 handoff 不无限追加。

切换 Agent 时提供仓库路径与本轮目标即可，要求其按统一入口加载项目上下文。不要要求用户手动重述已经记录的项目历史。

## 6. 多 Agent 与版本管理

用户或适用指令明确要求并行后，主负责者划分文件所有权并记录交接点。共享目录中避免同文件竞争；整体验证由主负责者完成。

当前已初始化 Git，默认分支为 main；当前工作分支以实际检查为准，origin 指向用户指定的私有 GitHub 仓库，见 [ADR 0003](../decisions/0003-github-version-control.md)。尚未配置 CI 或部署。提交、推送及合并依据本轮明确授权执行，不把首次推送请求扩展为永久自动发布规则，不把写入 changelog 当作已经发布。版本发布需用户明确要求，并记录版本、范围、检查和实际发布目标。
