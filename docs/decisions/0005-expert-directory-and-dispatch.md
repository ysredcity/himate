# ADR 0005：专家目录与可调度名单

- 日期：2026-11-07（Asia/Shanghai）
- 状态：已接受并实施
- 替代关系：无

## 问题

用户要求在桌面工作台增加专家市场、个人发布专家和最多10位的可调度名单；召唤需交接至既有首页Composer，未指定专家时只允许名单内场景匹配。本期继续前端Mock，不能引入平台服务或持久化。

## 选项

1. 将全部资料和状态嵌入AppConfig或复制一套独立工作台：会混淆配置与业务状态，并造成Composer、导航与会话分叉。
2. 在现有产品宿主中增加目录页面，数据、规则和呈现分别维护：复用侧栏和Composer，状态与会话生命周期保持一致。

## 结论

采用方案2。沿用已有capability-hub导航ID，产品标签为“专家”；AgentShell持有chat / experts页面选择、收藏、可调度名单及召唤交接。expert-data.ts定义12条目录示例和两位直接召唤专家；expert-rules.ts提供上限、去重与匹配纯函数；expert-page.tsx使用现有Base UI Tabs / Dialog / Button。

明确指定专家优先且不受自动名单约束；未指定时只匹配名单中的规则，名单移除即时影响后续委托，不改历史。当前仅人事 / 差旅支持直接召唤，其他条目按各自示例关键词参与名单内自动匹配，全部为本地模拟，“进入”保持无响应。匹配到旧Mock剧本时覆盖其专家身份，防止剧本内旧身份绕过名单。

## 影响与验证

没有新增依赖、后端、鉴权、持久化或跨端共享；刷新重置。目录页面切换关闭产物；召唤回首页只选专家，不自动发送。默认可调度为人事 / 差旅两位。

桌面gate增加test:experts，覆盖上限10、重复、移除后补位、名单范围、手动优先、无匹配、目录ID和头像资源。浏览器交互与响应式仍须另验，代码测试不代替页面验证。

## 2026-11-07 交互修订

用户后续明确删除收藏功能，宿主已移除收藏状态；可调度Tab对外命名为已安装，内部名单规则不变。市场 / 我的专家已安装Check禁用，仅已安装Tab提供删除安装；操作使用标准ButtonGroup常显于右上。此前关于收藏的描述仅记录初始需求，不再代表当前实现。

后续同日用户调整操作布局为卡片底部左右分置，右侧召唤 / 进入附MessageCircle / ChevronRight。ButtonGroup基础组件保留但此处不再使用；以设计契约及当前实现为准。
