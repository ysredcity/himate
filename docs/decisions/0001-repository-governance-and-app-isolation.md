# ADR 0001：根目录治理与应用隔离

- 日期：2026-10-21（Asia/Shanghai）
- 状态：治理原则继续有效；应用目录和包名由 [ADR 0002](0002-platform-specific-app-directories.md) 替代。本文保留原始决策记录。
- 依据：用户明确要求建立 changelog、上下文和文档治理，并将实际应用放入独立目录。

## 问题

应用代码与项目规则混放，既有上下文主要留在聊天中。模板还携带早期 Agent 的部署记忆，容易让新 Agent 把旧链接、旧目录或跳过检查建议当作当前事实。

## 选项

1. 只添加文档，代码仍在根目录：迁移小，但不能满足应用独立目录要求。
2. 根目录治理，`app/` 独立应用，npm workspaces 统一命令和 lockfile：结构明确，保留根目录开发体验。
3. `app/` 维护独立依赖锁，根目录另做 npm wrapper：可运行，但引入两套安装语义和依赖来源。

## 结论

采用选项 2。根目录维护统一 Agent 契约、上下文、changelog、文档和治理检查；`app/` 包含所有产品源代码、静态资源、构建配置和应用 gate。保留单一根 lockfile，根命令转发至 `@himate/web`。

Agent 专用入口只做指针，不复制规则。旧模板记忆原样归档，不导入当前部署事实。UI 行为与素材内容在本次迁移中保持原样。

## 后果

- 新 Agent 能用固定读取顺序接手，关键约束无需依赖聊天上下文。
- 部署产物路径由 `dist/` 改为 `app/dist/`；未来部署需明确采用新路径。
- 所有安装在根目录执行；不能在 app 内另建 lockfile。
- 相对链接和命令边界由自动检查覆盖，文档语义仍需维护者与 Agent 核对。
- 本次不初始化 Git、不创建远端、不引入 CI 或自动发布；这些应作为后续明确任务。

## 验证

本次实际检查记录在 [迁移计划的 Completion 节](../plans/2026-10-21-project-governance.md#completion)。根与 app 两级 gate、干净安装及预览恢复均通过。迁移前后 132 个源码与公开资源文件的 SHA-256 均一致；仅工程装配、文档和治理内容发生变化。
